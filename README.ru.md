# Good Pass

Небольшой образовательный сервис, который показывает, насколько пароль силён на самом деле, сколько времени уйдёт на его перебор и что именно изменить, чтобы он стал сильнее.

**Статус:** ранняя версия, продукт ещё складывается; намеренно не индексируется поисковиками · **Сайт:** https://good-pass.morgunov.tech (по-английски: https://good-pass.morgunov.tech/en/) · **Лицензия:** MIT · **English version:** [README.md](README.md)

## Что умеет

- **Анализ.** Энтропия в битах, оценка времени перебора, балл от «очень слабый» до «отличный», сильные и слабые стороны пароля и рекомендации — с примером и энтропией, которую добавляет каждая.
- **Проверка утечек.** Говорит, встречался ли пароль в известных утечках (Have I Been Pwned), не отправляя никуда ни пароль, ни его полный хеш.
- **Генератор.** Случайные пароли заданной длины и набора символов или запоминающиеся фразы из тематических словарей, плюс пять штук сразу.
- **Тренажёр памяти.** Показывает пароль пять секунд, потом проверяет, насколько точно вы наберёте его по памяти.
- **История, экспорт в PNG, горячие клавиши.** Последние десять проверок остаются в открытой вкладке; результат можно сохранить картинкой; основные действия — с клавиатуры: Ctrl/Cmd+G — сгенерировать пароль, Ctrl/Cmd+H — показать или скрыть его, Esc — закрыть тренажёр и историю.
- **Ставится как PWA.** После первой загрузки страница, генератор, тренажёр и темы работают офлайн; анализу и проверке утечек нужна сеть, и они об этом говорят. Светлая, тёмная, автоматическая и высококонтрастная тема.
- **Языки.** Русский и английский, переключатель в шапке страницы: интерфейс (`public/locales/`), анализ от API — балл, время перебора, сильные и слабые стороны, рекомендации, тексты ошибок (`src/i18n/`) — и словари генератора. Страница открывается на сохранённом выборе посетителя, иначе на английском для англоязычного браузера, иначе на русском; https://good-pass.morgunov.tech/en/ всегда открывается на английском, а переключение языка там переводит адрес на `/` (и обратно на `/en/` для английского).

## Приватность

- Проверка утечек k-анонимная: браузер считает SHA-1 пароля и отправляет только первые 5 символов хеша; сервер запрашивает у Have I Been Pwned (`api.pwnedpasswords.com`) все хеши с этим префиксом, а совпадение ищется в браузере. Ответ HIBP сервер держит в памяти 24 часа, по префиксу.
- Анализ выполняется на сервере (функция Cloudflare Pages) по HTTPS. Пароль нужен для одного ответа, не логируется и не хранится. На каждый анализ в лог уходит одна строка с длиной пароля, энтропией, баллом и языком; отклонённый запрос (не строка, пустой) или сбой логируется только с причиной.
- История живёт только в памяти страницы: в хранилище браузера ничего не пишется, при закрытии или перезагрузке вкладки она исчезает, а до того очищается одной кнопкой. Браузер запоминает только выбранные язык и тему.
- Стили и шрифты (дизайн-система morgunov.tech, IBM Plex) загружаются с https://s.morgunov.tech — сайта автора: как любой сервер, он видит ваш IP и браузер, не ставит cookie и не ведёт аналитику. Сама страница аналитику не подключает.

## API

Два `POST`-эндпоинта, JSON на вход и на выход; на проде их отдают Pages Functions, локально — Express. Обработчики общие (`src/api.js`), и тест проверяет, что оба отвечают одинаково.

```bash
curl -s -X POST -H 'content-type: application/json' \
  -d '{"password":"weekly-check-Storm#2045","lang":"en"}' \
  https://good-pass.morgunov.tech/api/v1/analyze
```

- `POST /api/v1/analyze` с `{ "password": "…", "lang": "en" }` возвращает балл, энтропию, оценку времени перебора, сильные и слабые стороны и рекомендации. Пароль длиннее 128 символов — `400`; тело запроса больше 5 КБ — `413`, некорректный JSON — `400`.
- `lang` — `"ru"` или `"en"`, язык всех текстов ответа, ошибок тоже. Поле необязательное: без него или с любым другим значением ответ русский, ровно такой же, как до появления `lang`. Ошибки, которые случаются до чтения тела (больше 5 КБ, некорректный JSON), берут первый язык из `Accept-Language`. `score` (`empty`, `very_weak`, `weak`, `medium`, `strong`, `excellent`) и `weaknessCodes` одинаковы на всех языках — для кода, который что-то делает с результатом.
- `POST /api/v1/breach-check` с `{ "hashPrefix": "5BAA6" }` — первые 5 hex-символов SHA-1 — возвращает подходящие суффиксы с числом утечек; `lang` работает и здесь. Если Have I Been Pwned недоступен, ответ всё равно `200`: пустой список и поле `error`, и страница пишет, что проверка временно недоступна, а не падает.
- Локальный Express ограничивает API 60 запросами в минуту с одного IP. У Pages Functions лимита нет: binding ограничения частоты в Cloudflare есть только у Workers, Pages Functions его не поддерживают, а правило WAF в зоне morgunov.tech ограничило бы только good-pass.morgunov.tech: good-pass.pages.dev отвечает тем же API вне зоны.
- Только в Express: `GET /healthz` (`{"status":"ok"}`) и устаревший `POST /api/analyze` — редирект `307` на `/api/v1/analyze`.

## Стек

Статический фронтенд в `public/` (ванильные JS-модули, [дизайн-система morgunov.tech](https://s.morgunov.tech) для стилей и шрифтов, service worker для офлайна). API — функции Cloudflare Pages в `functions/api/v1/`; локально ту же логику (`src/api.js`) отдаёт Express (`src/server.js`), на проде он не работает — нужен для разработки и тестов. `/en/` — та же страница с английскими тегами для превью ссылок: LinkedIn, Telegram и другие превью читают теги `og:`, не запуская страницу, поэтому `src/englishPage.js` переписывает `<head>` из `public/index.html` по-английски (заголовок, описание, канонический адрес, `og:url`, картинку, `og:locale`); отдаёт её функция Pages в `functions/en/`, локально — Express. Тексты API — по словарю на язык в `src/i18n/`. Тесты на встроенном `node:test`.

Для поисковиков и ИИ-ассистентов: пока сервис не готов, владелец держит его вне поисковой выдачи. `public/_headers` отдаёт `X-Robots-Tag: noindex` на каждом пути (локально то же делает `src/server.js`), в `public/index.html` стоит `<meta name="robots" content="noindex">`, который наследует `/en/`, sitemap нет, а `public/robots.txt` даёт Content Signals `search=no, ai-input=yes, ai-train=yes` ([contentsignals.org](https://contentsignals.org): сайт можно использовать в ответах ИИ и для обучения ИИ, но не показывать в поиске). Роботы по-прежнему допущены: чтобы увидеть `noindex`, робот должен загрузить страницу. На странице остаются блок JSON-LD `WebApplication` (автор — тот же `Person`, что на s.morgunov.tech) и мета подтверждения Яндекс Вебмастера, а `public/llms.txt` простым текстом описывает сервис, приватность и API. Чтобы снова индексироваться: убрать строку заголовка, мета-тег и `search=no`, вернуть `sitemap.xml` со строкой `Sitemap:` в `robots.txt` и поднять имя кеша service worker.

## Локальный запуск

Node: текущий LTS (`lts/*`, как в CI); больше ничего ставить не нужно.

```bash
npm install
npm start                          # Express на http://localhost:3000
npm run dev                        # то же с явным NODE_ENV=development (HSTS и кеш статики на сутки — только в production)
npx wrangler@4 pages dev public    # как на проде: Pages Functions и _headers
```

## Тесты

```bash
npm test
```

Тесты покрывают анализатор и рекомендации, разбор ответа HIBP, HTTP API через Express и продовую схему (`test/pages.test.js`): Pages Functions отвечают точно так же, как Express, на обоих языках, до HIBP доходит только 5-символьный префикс, недоступный HIBP возвращается как `200` с `error`, `public/_headers` отдаёт ту же CSP, что и сервер, `noindex` на каждом пути (Express тоже) и на адресе pages.dev, а в HTML нет ничего инлайнового, что CSP заблокировала бы (блок JSON-LD — данные, браузер их не выполняет); в каждой группе `robots.txt` есть сигналы, sitemap в нём не назван и не отдаётся, в `index.html` и на `/en/` стоит мета `noindex`, `llms.txt` отдаётся как текст, JSON-LD разбирается и называет канонический адрес; `/en/` находит каждый тег, который переписывает, не оставляет в них русского, сохраняет статические заголовки, одинаково отвечает через функцию и Express и ссылается на английский PNG 1200×630. `test/i18n.test.js` проверяет языки: выбор языка страницей (и на `/en/`), одинаковые ключи во всех словарях, ни одной кириллической буквы в английском, словари генератора.

CI на каждый pull request запускает тесты, `npm audit --omit=dev --audit-level=high` и поиск секретов gitleaks; для `main` обе проверки обязательны. Dependabot раз в неделю открывает один сгруппированный npm PR; минорные и патч-обновления мержатся сами после зелёного CI, мажорные ждут человека.

## Деплой

Cloudflare Pages деплоит `main` на https://good-pass.morgunov.tech автоматически: `public/` с заголовками из `public/_headers` и функции из `functions/` (API и `/en/`).

Service worker кеширует статику под одним именем (`goodpass-v13` в `public/sw.js`); меняете страницу, CSS или JS — поднимайте его, иначе вернувшиеся посетители останутся со старыми файлами: 1.4.3 поднял его из-за мета-тега `noindex` в `index.html`, который иначе до вернувшихся посетителей не дошёл бы, 1.5.0 — из-за общей шапки. Шапка, меню языка и темы, основная кнопка и подвал общие для сервисов morgunov.tech: разметка из раздела «Service chrome» руководства `ds/v1/USAGE.md` в [about-me-page](https://github.com/morgunovtech/about-me-page), стили — `components.css` дизайн-системы. Сценарий шапки `public/chrome.js` — копия `https://s.morgunov.tech/ds/v1/chrome.js` на своём адресе (CSP разрешает скрипты только отсюда); `test/pages.test.js` сверяет её хеш, и после обновления копии число в тесте меняется вместе с ней. `public/theme-init.js` ставит тему до первой отрисовки. Превью для ссылок, PNG 1200×630, — отрисовки общего шаблона карточки (дизайн-система morgunov.tech, `templates/share-card`, карточки `goodpass-ru` и `goodpass-en`; правила — её `guidelines/IMAGERY.md`): `public/og-image.png`, русское, для `/` и `public/og-image-en.png`, английское, для `/en/`. Текст карточки меняется в `cards.js` шаблона; карточка, нарисованная в этом репозитории, снова разойдётся с остальными ссылками morgunov.tech. Версии по SemVer перечислены в [CHANGELOG.md](CHANGELOG.md); номер в `package.json` и `src/log.js` (поле `version` каждой строки лога) совпадает с верхней записью.

## Что проект создаёт снаружи

- Проект Cloudflare Pages `good-pass`, который отдаёт `main` на своих доменах good-pass.morgunov.tech (основной) и gpass.morgunov.tech (правило переадресации Cloudflare отправляет его на основной с 308, сохраняя путь и query: в отличие от 301, при 308 `POST` остаётся `POST`, так что вызовы API на старый адрес продолжают работать); их DNS-записи — в зоне morgunov.tech. https://good-pass.pages.dev — технический адрес проекта в Cloudflare: он продолжает работать, а `public/_headers` просит поисковики его не индексировать. Снести: удалить проект, обе DNS-записи и правило переадресации в панели Cloudflare.
- На GitHub: защита ветки `main` с обязательными проверками `test · audit` и `secrets`, «Allow auto-merge» для workflow Dependabot, сам Dependabot.
- Ключей API нет: range API Have I Been Pwned работает без ключа.
- SonarQube Cloud: приложение GitHub на этом репозитории и проект `morgunovtech_good-pass` (автоматический анализ, в репозитории нет ни конфига, ни токена). Снести: удалить проект на sonarcloud.io и убрать репозиторий из установки приложения.
- Поисковики: мета подтверждения Яндекс Вебмастера в `public/index.html` (чтобы убрать — удалить сайт в Вебмастере), адресный ресурс в Google Search Console (подтверждён через доменный ресурс morgunov.tech) и его импорт в Bing Webmaster. Пока сайт под `noindex`, регистрации остаются: по ним видно, как страницы уходят из выдачи. Позже владелец может удалить ресурсы; если там был добавлен sitemap, он теперь отвечает 404, и его стоит удалить.
